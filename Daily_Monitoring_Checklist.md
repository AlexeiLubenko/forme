# Ежедневный регламент мониторинга резервов

## До публикации отчета
1. Получить дневной срез и убедиться, что отчетная дата одна.
2. Запустить Python pipeline.
3. Проверить `DQ status`. При `FAIL` отчет не публиковать.
4. Проверить `bridge_check_mln = 0`.

## Основной анализ
1. Зафиксировать Reserve, EAD, Reserve rate, Delta DoD, Delta MTD.
2. Разобрать точный мост `NEW / EXIT / EXISTING`.
3. Разобрать `primary_driver` внутри движения и обязательно смотреть `driver_flags` для multi-factor договоров.
4. Проверить миграции Stage: 1->2, 1->3, 2->3 и обратные.
5. Проверить новые дефолты, ухудшение просрочки, rating downgrade, PD/LGD/EAD jumps.
6. Разобрать TOP-10/50 договоров по абсолютному Delta Reserve.
7. В Qlik проверить концентрацию эффекта по отрасли, риск-сегменту, бизнес-сегменту, субпортфелю, рейтингу, просрочке и валюте.

## Что написать в ежедневном комментарии
> На отчетную дату общий резерв составил ___ млн BYN, изменение за день ___ млн, MTD ___ млн. Мост: NEW ___; EXIT ___; EXISTING ___. Контроль сходится / не сходится. Основные причины: ___. Миграции Stage: ___. Top-10 договоров формируют ___% дневного изменения. DQ status = ___. Требуют проверки / действия: ___.

## Действия
Для каждого существенного наблюдения зафиксировать: проблема, клиент/сегмент, действие, ответственный, срок, статус.
